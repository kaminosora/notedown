# Notedown 1.3.1 验证记录

日期：2026-11-14。基于已发布的 1.3.0（`60f8f7d`），版本 1.3.1 / versionCode 7。

## 交互修正

手机反馈表明，编辑器内长按单元格会与输入焦点、键盘及有限的编辑视口争用。此次移除富文本表格拖动插件，将行列重排和单元格交换放在普通阅读页面。

- 点状行／列柄位于表格外侧，沿用列表 `⠿` 的样式；预览、手柄不进入保存内容。
- 单元格交换移动内容节点，保留格式、复选框、LaTeX；行列重排保持表头及分区位置语义。
- 有效松手后自动保存，失败恢复已保存内容。触摸取消、拖出表格、离开页面或打开编辑器／弹窗时清理会话。
- 页面上下边缘与宽表横向滚动使用阅读视口；编辑模式保留正常文字输入、选择和表格增删。
- 列表与表格手势互斥，防止长按单元格时同时移动外层列表项。列表落位动画中的待保存操作在进入编辑器前完成。

## 自动化检查

`npm test` 全套通过。随后针对 Android 触摸捕获兼容修正，重新完整运行表格及显示套件，通过 19 项和 9 项；各套件最终合计 **134 项／组**：存储 27、端到端 6、编辑器 45、存储失败 UI 8、公式 12、阅读表格 19、公式 UI 8、显示比例 9。

MuMu 原生共 **17 组** 通过：

- 默认密度下阅读行列排序、单格交换与保存、编辑无表格拖动、整页边缘滚动和取消、公式键盘输入及保存重开，共 5 组。
- 原编辑体验回归 9 组，覆盖键盘显隐、长文输入、跨屏选区固定端、光标手柄、横屏和原生保存。
- 手机密度与 125% 字体下比例保存／重启、阅读表格落点与键盘不弹出、编辑和公式键盘避让，共 3 组。

原生首次检查发现 WebView 110 的 implicit pointer capture 转移会产生旧目标的 `lostpointercapture`。已使用稳定的阅读容器捕获，区分旧目标转移与真正丢失，并抑制阅读表格原生长按选择；修复后完整原生检查通过。浏览器另加入对应捕获转移和静止长按不自动滚动的回归。

网页测试使用独立临时服务器和 Chromium，包含阅读态行列移动／单元格交换、富文本内容往返、保存失败回滚、退出取消、页面及横向滚动、列表嵌套、多个表格、无键盘焦点、缩放比例与编辑器不再拦截长按。

原生检查使用 MuMu Player 12 / Android 15 / WebView 110.0.5481.154.1，独立 QA 包。1440×2560 下分别验证 360dpi／系统字体 100%，以及 560dpi／系统字体 125% 和应用 65% 等比例。Fcitx5 Android 0.1.3 提供可实际观察和点击的软键盘，阅读拖动检查在长按期间、松手后均确认 IME 未显示，页面高度不被键盘压缩。

## 边界

尚未在 Redmi K80 Pro 实体机或其他 OEM WebView／输入法组合验收。含合并或不规则单元格的表格只支持单元格内容交换；整行整列移动不改变其跨度结构。阅读态排序自动保存，不进入富文本编辑器撤销历史；单元格内的列表长按优先作为单元格移动。
