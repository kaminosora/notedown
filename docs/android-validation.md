## 当前验证状态

已使用项目 `.tools/` 下的便携 JDK 17、Android SDK 35 和 Gradle 8.11.1 构建，并在 MuMu 12 / Android 15 安装验收。网页与存储验证见 [verification.md](verification.md)。没有改动系统 JDK / SDK 安装或永久环境变量。

测试环境：Android 15 / API 35，型号标识 23116PN5BC，`com.android.webview 110.0.5481.154.1`，1440×2560、360dpi，字体缩放 1.0，横竖屏。MuMu 原有搜狗桥接输入法不显示有高度的屏幕键盘，因此临时使用 Fcitx5 Android 0.1.3 的英语及拼音键盘；测试后恢复原输入法与旋转设置。Fcitx5 的物理键输入会收起虚拟键盘，所以键盘验收使用 ADB 原生触摸点击软键，不用 `adb input text` 代替。

编辑测试使用独立包 `io.github.kaminosora.notedown.qa`，与原应用数据隔离。发布 APK 沿用 1.1.1 的调试签名；最终覆盖升级与数据校验结果见 [verification.md](verification.md)。

### 实测结果

- 自动化原生集成 9 组通过：标题键盘避让；长文末尾软键输入；三轮键盘显隐；格式、任务、代码、表格和块操作；自定义选区手柄原生拖动与边缘滚动；正反向选区滚动保持；光标手柄保持折叠；横屏键盘；模式往返、原生 AtomicFile 保存及重新打开。
- 竖屏无键盘的 WebView 高度为 1104 CSS px，键盘展开后为 723 CSS px；没有双重占位。长文滚动后工具栏与滚动区顶边对齐，正文不再从工具栏上方露出。
- 额外实际点击拼音软键输入 `nihao`，选择“你好”，换行、再次输入并删除；最终输入位置在键盘上方（光标底部约 701px，可视区 723px），中文无丢失或重复。
- 系统原生长按选词后，拖动上端手柄扩展到多段文字，另一端保持文档位置 1030；再滚到文首、中部、文末，正反向端点不变且始终位于正文内。这是当前 WebView 的抽查，不代表所有系统手柄组合。
- 自适应图标资源经 AAPT2 编译，浏览器预览检查覆盖圆形、圆角方形和单色形式；覆盖升级后已检查 MuMu 启动器中的新图标。

报告及截图保存在本地忽略目录 `.test-artifacts/android15/`，包括 `report.json`、`metadata.json`、`chinese-input.json`、`native-selection.json`。原笔记备份属于私有数据，不纳入 Git 或发行附件。

输入法行为参考：[Fcitx5 Android 官方发布说明](https://github.com/fcitx5-android/fcitx5-android/releases)。

### 重现自动化检查

设备需使用上述分辨率、密度及 Fcitx5 0.1.3 **英语**软键盘；软键坐标针对该配置，不是通用设备驱动。先按项目构建说明准备 JDK / SDK，再执行：

```powershell
./gradlew.bat -I tests/android-qa.init.gradle :app:assembleDebug
$env:ADB_PATH = '<MuMu 或 SDK 的 adb.exe 路径>'
$env:ANDROID_SERIAL = '127.0.0.1:16384'
& $env:ADB_PATH -s $env:ANDROID_SERIAL install -r .tmp/qa-build/outputs/apk/debug/app-debug.apk
npm run test:android
```

脚本固定测试 `.qa` 包，只保存测试笔记，不清理原应用；结束后恢复脚本开始时的旋转设置。拼音与系统原生选择手柄是额外人工坐标操作，不计入 9 组自动化结果。

## 原生实现变化

- 在根布局处理系统栏、屏幕缺口与软键盘占位，改变 WebView 实际可用大小，让网页中的固定定位编辑面板也能避开键盘。
- 保留顶部系统安全区外的 10dp 缓冲。左右和底部采用相应系统遮挡的最大值，避免重复相加。
- Android 11 / API 30 及以后使用类型化 WindowInsets；API 29 使用 Builder 的旧接口；API 26–28 使用旧 system-window inset 接口。Manifest 保留 adjustResize。
- 已由原生布局处理的 insets 归零后继续传给 WebView，避免新 WebView 额外应用同一占位，以及键盘关闭后遗留空白。
- 原生导入在 BOM 解码后判断实际 NUL 字符，允许正常 UTF-16LE / UTF-16BE 文本中的零字节。

设计依据：[Android 官方 WebView window insets 文档](https://developer.android.com/develop/ui/views/layout/webapps/understand-window-insets)。

## 设备记录

每次验收请记录以下项目，不要只写 Android 大版本：设备型号、Android / API 版本、WebView 提供者与完整版本、输入法名称与版本、手势或三键导航、字体/显示缩放、横竖屏、APK 提交或构建标识。

## 软键盘和布局

1. 新建笔记，分别点击标题、富文本正文、Markdown / HTML 源码及链接地址输入框。键盘出现后输入处和必要操作按钮应可达，顶部状态栏/挖孔不遮挡按钮。
2. 在超过三屏的正文末尾持续输入中文，覆盖拼音未确认、选择候选、表情、换行、删除。光标及新输入行应保持可见，合成文字不应丢失、重排或重复。
3. 连续打开/关闭键盘五次，切换输入法、候选栏高度与横竖屏。检查没有重复留白、底部残留大空白、内容高度越来越小或焦点反复丢失。
4. 分别在手势导航、三键导航、分屏模式重复检查。浮动/分离式键盘可能不提供常规 IME 遮挡；将实际表现单独记录，不能按普通底部键盘结果判定。
5. 长文编辑中按系统返回：先检查输入法自身的返回行为，再检查编辑器返回/取消行为。确认没有误关闭应用或丢失已保存笔记。

## 选择和滚动

1. 在正文中长按选词，将上、下选择手柄分别拖向编辑区边缘，让另一端滚出可视范围。只允许活动端跟随拖动，固定端应保持原文档位置。
2. 正向和反向选择都覆盖至少两屏，包含标题、列表、代码、表格以及图片相邻位置。工具栏、页面标题、提示和其他界面文字不得进入正文选区。
3. 将拖动端移到工具栏、键盘上缘或正文以外再移回；松手、取消触摸、旋转屏幕后，自动滚动应停止，不得继续漂移。
4. 没有选区时拖动光标、普通滑动阅读、双指缩放分别检查；正文的普通滚动不得被误当作选区拖动。
5. 选中文字后滑动工具栏再点击格式操作；滑动不应误触命令，应用范围应保持原选区，中文输入法不应反复收起。
6. 分别启用工具栏“光标”和“选区”，使用应用提供的手柄重复跨屏测试；固定端滚出屏幕后不应自动吸附到视口边缘。切换模式、关闭编辑器或取消触摸后手柄及滚动会话应清理。

## 内容块与保存

1. 在列表、任务、引用、代码块、表格、图片、分割线前后添加段落，执行移动、删除、撤销和重做。检查顺序、内容和任务勾选状态。
2. 富文本、Markdown、HTML 模式往返后保存并重新打开。检查非文本块及中文没有丢失，编辑操作界面的按钮不进入笔记正文。
3. 使用系统文件选择器分别导入带 BOM 的 UTF-16LE、UTF-16BE、UTF-8，以及无 BOM UTF-8 / GB18030 样本，包含 ASCII、中文、换行与表情。正常文本应导入成功；解码后包含实际 NUL 字符的样本应提示不是文本。
